# 프루퍼 AX 서비스 커리큘럼 스펙

프루퍼 주식회사가 기업에 제공하는 AX(AI Transformation) 서비스의 커리큘럼 단일 출처입니다.
랜딩 페이지(`ax.proofer.tech`)가 노출하는 모든 커리큘럼 문구는 이 문서를 근거로 삼습니다.
페이지 구조와 전환 설계는 `docs/ax-landing-spec.md`에 따로 적혀 있습니다.

이 문서의 내용은 사람이 단일 출처로 지정한 `프루퍼_AX_커리큘럼_기획서`를 레포 문서 규약에
맞춰 옮긴 것입니다(요구사항 `7f2ab67e` 질문 1-2의 (가)안, 답변 `4eac5887`).
2026-09-01 이전에 이 문서가 담고 있던 강의 네 레벨과 해커톤 5단계, 컨설팅 4단계 체계는
폐기되었습니다.

## 0. 설계 근거

### 프루퍼가 이 교육을 하는 이유

기업의 AI 도입은 도입 여부를 고민하는 단계를 지났습니다. 남은 질문은 도입한 AI를 어떻게
실제 성과로 바꾸느냐입니다. 그런데 시중의 AI 교육 대부분은 도구 사용법을 알려주는 데서
멈춥니다. 수강생은 강의장에서는 감탄하지만 자리로 돌아오면 자기 업무에 무엇을 어떻게 붙일지
막막해합니다. 교육 예산은 집행되었는데 현업이 일하는 방식은 그대로입니다.

프루퍼는 교육회사가 아니라 그로스 컨설팅 회사입니다. 현장에 들어가 진짜 문제를 다시
정의하고, 필요하면 앱과 서버와 AI까지 직접 만들어 운영효율을 끌어올려 왔습니다. 어려운
시기에 한 기업에 합류해 1년 만에 팔리는 회사로 만들고 약 1,400억 규모의 매각을 이끈 경험이
있습니다. 이 매각 규모는 사람이 대외 공개를 승인했으므로 랜딩 페이지가 근거로 쓸 수
있습니다(답변 `4eac5887` 1-1).

그래서 다른 교육과 세 가지가 다릅니다.

- 강사가 실제로 만들고 운영하는 사람입니다. 실습 예제가 시연용이 아니라 현업에서 쓰던
  것입니다.
- 특정 도구에 얽매이지 않습니다. Claude, Copilot, Gemini, Cursor를 실무에서 다뤄 왔기 때문에
  고객사 환경에 맞는 도구를 중립적으로 권합니다.
- AI를 비용이 아니라 영업이익과 기업가치를 올리는 지렛대로 봅니다. 그래서 교육의 끝이
  "우리 회사에 무엇을 적용할까"로 이어집니다.

프루퍼는 사내에서도 AI로 일합니다. 사내 시스템을 AI에 연결하는 도구를 직접 만들어 쓰고,
반복 업무를 자동화 워크플로로 돌리며, 흩어진 사내 지식을 AI가 활용하도록 구조화해 왔습니다.
남이 만든 커리큘럼을 전달하는 것이 아니라, 실제로 그렇게 일하는 회사가 자기 방식을
가르칩니다.

### 세 상품이 하나의 흐름을 이룹니다

```
AX Lecture (저변 확대)
   -> AX Hackathon (실전 전환)
      -> AX Consulting (성과 실행)
```

강의로 조직 전반의 AI 활용력을 끌어올리고, 해커톤으로 그 힘을 사내 실제 문제에 붙여
돌아가는 결과물을 만들고, 컨설팅으로 그 결과물을 실제 서비스와 성과로 연결합니다. 프루퍼는
교육으로 고객을 만나 컨설팅으로 잇고, 컨설팅 실적으로 교육의 신뢰를 담보합니다. 고객사는
이 셋 중 필요한 지점부터 시작하면 됩니다.

### 참고 자료를 실적으로 쓰지 않습니다

이 커리큘럼은 프루퍼가 직접 설계한 것입니다. 설계할 때 기업 AI 교육 시장에 이미 나와 있는
과정들을 참고 자료로 훑었지만, **그 자료는 프루퍼의 자산이 아니고 프루퍼의 수행 실적도
아닙니다.** 따라서 이 문서의 어떤 항목도 프루퍼의 실적 근거로 쓰지 않고, 참고한 과정의
이름이나 고객사 이름을 이 문서와 랜딩 페이지 어디에도 적지 않습니다.
랜딩 페이지가 신뢰의 근거로 삼는 것은 `docs/ax-landing-spec.md`에 따로 정해 두었습니다.

### 세 상품에 공통으로 들어가는 것

카테고리와 무관하게 항상 포함하는 요소가 셋입니다.

1. 보안 수칙 - AI 입력은 곧 외부 전송이라는 원칙, 넣지 않는 자료의 목록, 더미 데이터 원칙.
2. 실습 우위 - 이론 설명 뒤에 반드시 수강생 본인의 업무 자료로 하는 실습이 붙습니다.
3. 결과물 공유 - 실습 산출물을 공유 보드에 올리고 피드백을 받는 절차가 마지막에 붙습니다.

## 1. AX Lecture (AX 강의)

### 정의

임직원의 AI 활용력을 수준별로 끌어올리는 강의형 과정입니다. 전 직원 리터러시부터 파워유저
양성까지, 조직의 AI 저변을 넓히는 가장 빠른 경로입니다.

### 구성

수준에 따라 네 트랙으로 나뉘고, 여기에 의사결정권자를 위한 리더 과정을 더합니다.

| 트랙                    | 대상                                     | 기간          | 결과물                                        |
| ----------------------- | ---------------------------------------- | ------------- | --------------------------------------------- |
| L1. AI 리터러시         | 전 직원                                  | 반일에서 하루 | 자기 업무 세 가지를 AI로 다시 설계한 워크시트 |
| L2. 도구 실무           | 사무직 실무자                            | 하루에서 이틀 | 자기 반복 업무 하나를 자동화한 워크플로       |
| L3. 직무 특화           | 직무 조직 단위                           | 고객사와 협의 | 직무 표준 프롬프트와 재사용 워크플로          |
| L4. 파워유저와 에이전트 | 파워유저, 개발 인접 직무, 사내 AI 챔피언 | 이틀에서 사흘 | 팀에 배포하는 작은 도구 또는 에이전트 하나    |
| 리더 과정               | 임원과 직책자                            | 두세 시간     | 자사의 AX 우선순위 한 장                      |

### L1. AI 리터러시 (전 직원)

생성형 AI의 기본기, 프롬프트 작성법, 업무 적용 감각, 보안과 윤리 기준을 다룹니다. 반일에서
하루 과정이며, 수강생은 자기 업무 세 가지를 AI로 다시 설계한 워크시트를 들고 나갑니다.
무엇이 되고 무엇이 안 되는지를 실패 사례로 짚어, 민감한 데이터나 규제 업무에서 선을 긋는
법까지 가르칩니다.

### L2. 도구 실무 (Claude, Copilot, Gemini 중 선택)

사무직 실무자가 선택한 도구로 문서와 데이터와 보고서 업무를 자동화합니다. 하루에서 이틀
과정이며, 수강생은 자기 반복 업무 하나를 실제로 자동화한 워크플로를 만듭니다. 고객사의 도구
환경에 맞춰 트랙을 고르고, 도구 사용법이 아니라 업무를 도구에 맞게 다시 설계하는 법에
초점을 둡니다.

### L3. 직무 특화

연구, 기획, 영업, 인사, 재무, 안전, 품질, 물류처럼 직무 조직 단위로 진행합니다. 남의 사례가
아니라 자기 직무의 실제 데이터와 문서로 실습하고, 직무 표준 프롬프트와 재사용 워크플로를
확립합니다. 프루퍼가 사내 데이터를 구조화해 온 방식을 직무 맥락 설계에 적용해, 단발성
프롬프트가 아니라 조직에 남는 자산을 만듭니다.

### L4. 파워유저와 에이전트

파워유저와 개발 인접 직무, 사내 AI 챔피언을 대상으로 합니다. Claude Code나 Cursor로 직접
만들고, 여러 에이전트를 엮어 설계하며, 사내 시스템을 AI에 연결합니다. 이틀에서 사흘
과정이며, 팀에 배포하는 작은 도구나 에이전트 하나를 완성합니다. 프루퍼가 실제로 구축해
운영하는 사내 도구를 교보재로 삼아, 시연에서 끝나지 않고 배포까지 가는 것을 목표로 합니다.

### 리더 과정 (임원과 직책자)

의사결정권자를 대상으로 두세 시간 안에 AX 전략 판단, 투자 결정, 조직 도입 로드맵을 다룹니다.
수강 후 자사의 AX 우선순위를 한 장으로 정리해 나갑니다. AI 도입을 비용이 아니라 영업이익과
기업가치의 지렛대로 보는 관점을 전달하고, 조직의 진짜 문제를 발굴합니다.

### 운영 방식

- 집합 강의와 실습을 기본으로 하고, 필요하면 온라인 송출을 병행합니다.
- 주강사 한 명에 분반별 기술튜터를 붙여 실습 밀도를 확보합니다.
- 실습 결과물은 공유 보드로 모으고, 사전과 사후 설문을 표준화합니다.
- 사전 환경 세팅 가이드를 미리 배포하고 당일 접속을 점검합니다.
- 과정이 끝나면 각 조직이 뽑은 적용 후보를 회수해 다음 단계로 잇습니다.

## 2. AX Hackathon (AX 해커톤)

### 정의

강의에서 배운 것을 사내 실제 문제에 붙여 돌아가는 결과물을 만드는 실전 과정입니다. 교육과
컨설팅을 잇는 다리이며, 프루퍼가 기업 AI 심화 해커톤을 코치한 경험을 바탕으로 삼습니다.

### 프루퍼의 방식

- 결과물이 시연에서 끝나지 않습니다. 프루퍼는 실제로 배포하고 운영하는 회사이므로, 쓸 만한
  결과물을 실제 서비스로 잇는 길을 압니다.
- 심사 기준이 멋진 데모가 아니라 밸류입니다. 업무 시간을 얼마나 줄였는지, 실제 데이터로
  돌아가는지, 다른 팀으로 넓힐 수 있는지를 봅니다.
- 코치가 실전 빌더입니다. 막히는 지점에서 실제 구현을 함께 풉니다.

### 포맷

| 포맷           | 기간          | 결과물                 |
| -------------- | ------------- | ---------------------- |
| 스프린트       | 하루          | 문제 하나의 프로토타입 |
| 해커톤         | 이틀에서 사흘 | 팀별 결과물과 심사     |
| PBL 인큐베이터 | 4주에서 8주   | 파일럿 수준의 결과물   |
| 콘테스트       | 시즌 단위     | 사내 배포 후보 우승작  |

### 진행

문제 발굴 워크숍으로 시작합니다. 각 팀이 AI로 없앨 반복 업무나 풀고 싶은 문제를 정하고,
프루퍼가 그 문제의 크기를 함께 가늠합니다. 킥오프에서 도구를 세팅하고 팀을 짜고 데이터를
준비한 뒤, 코치가 붙어 빌드를 돕습니다. 심사는 절감 시간, 완성도, 재사용성, 배포 적합성을
기준으로 하고, 유망한 결과물은 컨설팅 과정으로 넘겨 실제 서비스로 만듭니다.

교육 예산을 실제로 쓰는 도구 자산으로 바꾸려는 고객사를 위해, 우승작 하나를 프루퍼가 짧은
스프린트로 배포 수준까지 끌어올리는 옵션도 둡니다.

## 3. AX Consulting (AX 컨설팅)

### 정의

프루퍼의 본업입니다. 진단부터 전환, 운영까지 이어집니다. AI 활용법을 가르치는 데 그치지
않고, 회사가 일하는 방식과 수익 구조를 AI로 다시 설계해 직접 만들고 운영합니다.

### 세 층위

- **비즈니스와 조직** - 사업과 수익 구조를 다시 설계하고, 채용과 육성, 역할을 재편합니다.
  AI 도입을 조직의 관점에서 봅니다.
- **개발과 구축** - 기획부터 앱, 서버, AI까지 직접 구현하고 검증합니다. 사내 도구와
  에이전트를 만들고 데이터를 정비합니다.
- **진단과 전환** - 현행 프로세스를 진단하고 AI 전환의 우선순위를 세워 파일럿을 설계합니다.

### AX 특화 서비스

1. 프루퍼가 사내에서 쓰는 AI 기반 개발 방식을 고객사 조직에 이식합니다.
2. 고객사의 사내 시스템과 문서, 데이터를 AI에 연결하는 도구를 구축합니다.
3. 사내에 흩어진 지식과 데이터를 AI가 활용하도록 구조화합니다.
4. 반복 업무를 실제 자동화 워크플로로 구현합니다.
5. 규제와 민감 데이터 환경에서도 AI를 도입하도록 설계합니다.

### 참여 방식

진단으로 시작해 파일럿으로 효과를 확인하고, 실행 단계에서 실제로 만들어 운영하며, 성과를
기업가치 관점에서 검증합니다. 프루퍼는 실무에 직접 참여하고, 비용은 프로젝트 참여 대가와
성과 인센티브로 구성합니다. 성과가 나야 프루퍼의 몫도 나오는 구조입니다.

리더 과정에서 나온 우선순위와 해커톤에서 나온 결과물이 그대로 이 진단의 입력이 됩니다.
교육에서 찾은 문제를 컨설팅에서 실제 서비스로 만듭니다. 프루퍼 모델의 핵심이 이 연결입니다.

## 4. 통합 로드맵과 패키지

고객사는 필요한 단계부터 시작할 수 있고, 아래처럼 묶어 제안할 수도 있습니다.

| 패키지       | 구성                                          | 목적                  |
| ------------ | --------------------------------------------- | --------------------- |
| 스타터       | 전 직원 리터러시 + 리더 과정                  | 조직 전반의 인식 형성 |
| 그로스       | 직무 특화 강의 + 해커톤                       | 실전 전환             |
| 트랜스폼     | 해커톤 우승작 배포 스프린트 + 컨설팅 진단     | 성과 실행 착수        |
| 엔터프라이즈 | 전 과정 롤아웃 + 사내 도구 구축 + 컨설팅 실행 | 전사 전환             |

견적은 상품마다 다른 기준으로 잡습니다. 강의는 인원과 일수 기준으로, 해커톤은 기간과 코치
규모와 결과물 수준으로, 컨설팅은 프로젝트 참여와 성과 인센티브로 산정합니다. 어느 경우든
교육 예산을 실제 도구 자산과 성과로 잇는 경로를 함께 제시합니다.

---

## 5. 도입 경로

고객사가 어디서 시작하든 같은 종착점으로 갑니다. 랜딩 페이지는 이 경로를 보여주고, 방문자가
자기 위치를 찾게 만드는 것을 목적으로 삼습니다.

| 고객사의 현재 상태               | 첫 제안                                       |
| -------------------------------- | --------------------------------------------- |
| AI를 아직 안 쓴다                | 스타터 패키지 (L1 리터러시 + 리더 과정)       |
| 도구는 샀는데 안 쓴다            | L2 도구 실무 + L3 직무 특화                   |
| 교육은 했는데 성과가 안 보인다   | 그로스 패키지 (직무 특화 강의 + 해커톤)       |
| 해커톤 결과물을 실제로 쓰고 싶다 | 트랜스폼 패키지 (배포 스프린트 + 컨설팅 진단) |
| 전사 체계가 필요하다             | 엔터프라이즈 패키지                           |

역방향도 성립합니다. 컨설팅으로 시작한 고객사는 로드맵 안에서 강의와 해커톤을 실행 수단으로
씁니다.

## 6. 기대 효과

- 임직원이 수준별로 AI 활용력을 갖춥니다.
- 강의가 실습 산출물과 사내 도구로 남아 교육 이후에도 자산이 됩니다.
- 현업의 진짜 문제가 발굴되고, 그중 일부를 실제 서비스로 전환합니다.
- 프루퍼가 AI 도입을 영업이익과 기업가치로 잇는 경로를 만듭니다.
