# 프루퍼 블로그 글 포맷 (PMD)

blog.proofer.tech 에 올라가는 글은 모두 이 문서의 포맷을 따른다. 포맷 이름은 프루퍼 마크다운, 줄여서 PMD 다(가칭). 사람과 LLM 이 같은 문서를 읽고 쓴다. 이 문서대로 쓰면 `pnpm blog lint` 를 통과한다.

원칙은 하나다. 렌더러가 그릴 줄 아는 블록만 쓴다. 검증기와 렌더러가 같은 블록 목록을 쓰기 때문에, 검증을 통과한 글은 반드시 화면에 그려지고 그려지지 않는 글은 검증을 통과하지 못한다. 포맷을 좁게 잡은 이유는 Medium 과 같다. 쓸 수 있는 모양이 적으면 글이 쌓여도 블로그 전체가 한 사람이 쓴 것처럼 일관되게 읽힌다.

글이 발행되기까지의 순서는 이렇다.

1. Claude Docs 에서 아래 템플릿으로 글을 쓴다
2. Docs 를 마크다운으로 내보낸다
3. `pnpm blog lint` 로 검사하고, 오류가 0 이 될 때까지 고친다
4. `pnpm blog preview` 로 실제 글 화면에서 확인한다
5. `pnpm blog publish --write` 로 DB 에 쓴다

## 새 글 템플릿 (Claude Docs)

Docs 에는 frontmatter 가 없다. 그래서 제목(H1) 바로 아래에 yaml 코드 블록을 하나 두고, 그 블록이 글 정보를 담는다. 새 글은 아래를 그대로 복사해서 시작한다.

````markdown
# AI 이후, UI 라이브러리를 걷어낸 이유

```yaml
subtitle: 컴포넌트 라이브러리를 들어내고 Tailwind 와 shadcn 만 남긴 뒤 화면 하나를 만드는 데 드는 시간이 어떻게 바뀌었는지 적는다
slug:
author: proofer
tags: [ai-native, 프론트엔드]
keywords: [UI 라이브러리, shadcn 도입, AI 프론트엔드 개발]
cover:
  src: https://...
  alt: 라이브러리를 걷어내기 전과 후의 컴포넌트 구조
published_at: 2026-10-11
canonical_url:
```

첫 문단은 도입이다. 첫 `##` 제목이 나오기 전에 글이 무엇을 다루는지 한두 문단으로 쓴다.

## 첫 번째 소제목

본문.
````

CLI 는 내보낸 마크다운에서 H1 을 `title` 로, 첫 yaml 코드 블록을 나머지 칸으로 읽는다. Docs 가 붙이는 날짜와 작성자 칩 줄은 버린다.

### 글 정보 칸

| 칸              | 쓰는 법                                                                                                                                  |
| --------------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `title`         | Docs 에서는 H1 이 제목이다. yaml 블록에 다시 쓰지 않는다. 60자를 넘으면 검색 결과에서 잘린다(PMD013 경고)                                |
| `subtitle`      | 40 ~ 160자. 글 목록과 검색 결과의 설명으로도 쓰인다                                                                                      |
| `slug`          | 글 주소. 비워 두면 생성한다                                                                                                              |
| `author`        | 저자 slug. `proofer`, `with-cto`, `hsol`, `maehong` 중 하나. 비우면 `proofer`                                                            |
| `tags`          | 1 ~ 3개. 아래 태그 사전의 slug 만 쓴다. 분류용이다                                                                                       |
| `keywords`      | 1 ~ 6개. 검색어다. 첫 항목이 주 검색어이고, 주 검색어는 제목이나 부제, 그리고 첫 문단이나 `##` 제목에 들어가야 한다(PMD018, PMD019 경고) |
| `cover`         | 대표 이미지. `src` 는 https 주소, `alt` 는 필수다                                                                                        |
| `published_at`  | 발행일. `YYYY-MM-DD`                                                                                                                     |
| `canonical_url` | 다른 곳에 원본이 있을 때만 쓴다. 보통은 비운다                                                                                           |

Medium 에서 옮겨 온 글에는 `updated_at`, `source`, `medium_post_id`, `medium_url` 같은 칸이 더 붙는다. 변환기가 채우는 칸이라 새 글에서는 쓰지 않는다.

## Docs 표기와 PMD 의 대응

Docs 에디터에는 이미지 캡션 칸과 링크 카드 블록이 없다. 그래서 Docs 에서는 아래 왼쪽 모양으로 쓰고, CLI 가 내보낸 마크다운을 오른쪽 PMD 로 바꾼다. 이 변환 덕분에 Docs 화면에서 쓰는 모양을 따로 바꿀 필요가 없다.

| Docs 에서 쓰는 모양            | PMD 로 바뀐 결과                      |
| ------------------------------ | ------------------------------------- |
| H1                             | frontmatter `title`                   |
| 날짜, 작성자 칩 줄             | 버린다                                |
| 첫 yaml 코드 블록              | 나머지 frontmatter                    |
| 이미지 바로 아래의 기울임 문단 | 그 이미지의 캡션 `![alt](url "캡션")` |
| 링크 하나만 있는 문단          | 링크 카드 줄(URL 만 남긴다)           |
| YouTube 링크 하나만 있는 문단  | 플레이어 임베드 줄                    |
| 문단 안 줄바꿈(Shift+Enter)    | 줄 끝 역슬래시 `\`                    |

Docs 는 체크리스트, 칩, 차트, 다이어그램 같은 블록도 만들 수 있다. 이런 블록은 Docs 에서 막을 방법이 없고, 내보낸 마크다운을 검증기가 오류로 걸러낸다. 처음부터 아래 허용 블록만 쓰는 편이 빠르다.

## 허용 블록

PMD 파일을 직접 쓸 때의 모양이다. Docs 에서 쓸 때는 바로 위 대응표의 왼쪽 모양을 따른다.

| 마크다운                                               | 화면            | 규칙                                                             |
| ------------------------------------------------------ | --------------- | ---------------------------------------------------------------- |
| frontmatter `title`                                    | 글 제목         | 본문에 `#` 을 쓰지 않는다                                        |
| frontmatter `subtitle`                                 | 부제            | 40 ~ 160자                                                       |
| `## 제목`                                              | 큰 소제목       |                                                                  |
| `### 제목`                                             | 작은 소제목     | `##` 아래에서만 쓴다                                             |
| 문단                                                   | 본문            | 문단 안 줄바꿈은 줄 끝 역슬래시 `\` 로만 한다                    |
| `**굵게**` `*기울임*` `` `코드` `` `[글](https://...)` | 인라인          | 링크는 https 와 mailto 만. URL 을 그대로 링크 글자로 쓰지 않는다 |
| `> 인용`                                               | 인용            | 한 단계만. 안에 제목, 목록, 이미지를 넣지 않는다                 |
| `- 항목` `1. 항목`                                     | 목록            | 중첩하지 않는다                                                  |
| 코드 펜스                                              | 코드 블록       | 펜스 첫 줄에 언어를 반드시 적는다(예: ts, bash)                  |
| `![대체 글](https://... "캡션")`                       | 그림과 캡션     | 혼자 한 문단을 차지한다. alt 필수, 캡션은 선택                   |
| 한 문단에 이미지 2 ~ 3장                               | 이미지 묶음     | 이미지마다 alt 필수                                              |
| `---`                                                  | 구분선          | 연달아 쓰지 않는다                                               |
| GFM 표                                                 | 표              | 머리 행 필수, 열 5개 이하, 셀 안에는 인라인만                    |
| 한 줄에 URL 하나                                       | 링크 카드       | 발행할 때 대상 페이지의 제목, 설명, 이미지를 받아 저장한다       |
| 한 줄에 YouTube URL 하나                               | 플레이어 임베드 | 임베드 허용 목록은 지금 YouTube 하나다                           |

## 금지

- raw HTML 전부. 주석 `<!-- -->` 도 포함한다
- 본문의 `#` 제목, `####` 이하 제목, 단계를 건너뛰는 제목(`##` 없이 `###`)
- 머리 행 없는 표, 열이 5개를 넘는 표
- 각주, 체크리스트, 취소선
- 중첩 목록, 중첩 인용
- alt 없는 이미지, 상대경로 이미지, http 이미지
- 끝 공백 두 칸이나 `<br>` 로 만든 줄바꿈

## 검증 규칙

검증기는 결과 한 건을 `<파일>:<줄> <규칙 id> <메시지> -> <고치는 방법>` 한 줄로 찍는다. 오류는 발행을 막고, 경고는 보고만 한다. LLM 에게 이 출력을 그대로 넘기면 줄 단위로 고칠 수 있다.

| id     | 등급 | 검사                                                                                 |
| ------ | ---- | ------------------------------------------------------------------------------------ |
| PMD001 | 오류 | raw HTML(주석 포함)                                                                  |
| PMD002 | 오류 | 허용하지 않는 제목 단계(본문 `#`, `####` 이하)                                       |
| PMD003 | 오류 | 제목 단계 건너뛰기                                                                   |
| PMD004 | 오류 | 이미지 alt 없음                                                                      |
| PMD005 | 오류 | 이미지가 한 문단 안에서 글과 섞임(이미지 2 ~ 3장만 있는 문단은 이미지 묶음으로 허용) |
| PMD006 | 오류 | 코드 펜스 언어 없음                                                                  |
| PMD007 | 오류 | 중첩 목록, 중첩 인용, 인용 안의 제목, 목록, 이미지                                   |
| PMD008 | 오류 | https, mailto 가 아닌 링크와 https 가 아닌 이미지                                    |
| PMD009 | 오류 | 역슬래시가 아닌 줄바꿈(끝 공백 두 칸, br)                                            |
| PMD010 | 오류 | frontmatter 스키마 위반(필수 칸, 길이, 태그 수)                                      |
| PMD011 | 오류 | 태그 사전에 없는 태그                                                                |
| PMD012 | 오류 | 링크 카드 줄에 URL 외 글자가 있음. 발행 때 카드 정보 받기에 실패해도 이 id 로 막힌다 |
| PMD013 | 경고 | 제목 60자 초과                                                                       |
| PMD014 | 경고 | 첫 `##` 앞에 도입 문단이 없음                                                        |
| PMD015 | 경고 | noslop 문체 점수 기준 초과. id 만 잡아 두었고 1단계에서는 검사하지 않는다            |
| PMD016 | 오류 | 표 규칙 위반(머리 행 없음, 열 5개 초과, 셀 안 블록)                                  |
| PMD017 | 오류 | keywords 개수가 1 ~ 6 밖임                                                           |
| PMD018 | 경고 | 주 검색어가 제목과 부제 어디에도 없음                                                |
| PMD019 | 경고 | 주 검색어가 첫 문단과 `##` 제목 어디에도 없음                                        |

각주, 체크리스트, 취소선은 따로 id 가 없고 금지 블록으로 오류가 난다.

## 태그 사전

`tags` 에는 아래 slug 만 쓴다. 글 하나에 1 ~ 3개를 달고, 주제 묶음 하나와 그 안의 세부 하나 정도가 기준이다. 표시 이름은 화면과 태그 페이지에 나온다. 사전에 없는 태그는 PMD011 오류다.

| slug                    | 표시                  | 뜻                                                 |
| ----------------------- | --------------------- | -------------------------------------------------- |
| `with-cto`              | with CTO              | with CTO 커뮤니티 글 전부                          |
| `행사-안내`             | 행사 안내             | 모집, 연사, 장소, 프로그램, 일정 같은 행사 전 공지 |
| `행사-후기`             | 행사 후기             | 행사 뒤 리뷰와 그날 오간 이야기                    |
| `커뮤니티-운영`         | 커뮤니티 운영         | 운영 회고, 운영진, 커뮤니티 방향과 온라인 공간     |
| `파트너십`              | 파트너십              | 스폰서와 파트너 소개, 파트너 모집                  |
| `개발자-생산성`         | 개발자 생산성         | 개발 조직의 성과와 생산성 측정                     |
| `dora-metrics`          | DORA Metrics          | DORA 지표와 연구                                   |
| `space-framework`       | SPACE Framework       | SPACE 프레임워크                                   |
| `엔지니어링-매니지먼트` | 엔지니어링 매니지먼트 | 팀 운영, 업무 관리 문화, 회고 방법                 |
| `ai-native`             | AI 네이티브           | AI 를 일하는 방식에 들인 이야기                    |
| `프론트엔드`            | 프론트엔드            | 웹 프론트엔드와 디자인 시스템                      |
| `프루퍼-소식`           | 프루퍼 소식           | 회사 소식                                          |

새 태그가 필요하면 글에 바로 달지 말고 이 사전과 `lib/blog/pmd/tags.ts` 를 먼저 고친다.

## CLI 사용법

세 명령 모두 Docs 에서 내보낸 마크다운과 PMD 파일을 둘 다 받는다. Docs 모양이면 먼저 PMD 로 바꾼 뒤 검사한다.

```bash
pnpm blog lint <글.md> [--images <폴더>]
pnpm blog preview <글.md> [--images <폴더>]
pnpm blog publish <글.md> [--images <폴더>] [--dry-run | --write]
```

`lint` 는 검사만 한다. 결과를 위의 한 줄 형식으로 찍고, 오류가 하나라도 있으면 종료 코드 1, 경고만 있으면 0 을 낸다. LLM 과 함께 쓸 때는 lint 출력을 넘겨 고치게 하고, 오류가 0 이 될 때까지 다시 돌린다. 오류가 남은 글은 발행하지 않는다.

`preview` 는 DB 에 쓰지 않고 실제 글 화면과 같은 컴포넌트로 글을 보여 준다. 검사 결과와 미리보기 주소 `/preview/<slug>` 를 찍는다. 오류가 있어도 미리보기는 만들고 오류 수를 함께 알려 준다. 미리보기 화면은 개발 모드에서만 열리므로 `pnpm dev` 를 띄운 상태에서 연다.

`publish` 는 기본이 `--dry-run` 이다. 아무것도 쓰지 않고 무엇을 할지만 찍는다. 새로 넣을지, 갱신할지, 바뀐 것이 없는지, 이전 본문 사본을 남길지, 이미지 업로드와 링크 카드 받기를 몇 건 할지가 나온다. 실제로 쓰려면 `--write` 를 준다.

- 검증 오류가 하나라도 있으면 `--write` 를 줘도 아무것도 쓰지 않는다
- 같은 slug 의 글이 이미 있으면 덮어쓰기 전에 직전 본문을 `article_revision` 에 남긴다. 내용이 같으면 쓰지 않는다
- Blob 에 없는 이미지는 Vercel Blob 에 올리고 본문 주소를 Blob 주소로 바꾼다
- DB 접속값(`POSTGRES_URL`)과 Vercel Blob 토큰이 있는 PC 에서만 돈다

## 새 글 이미지 넣기 (제안 단계)

> 이 절은 제안이고 아직 채택되지 않았다. 채택 여부는 사람이 정한다.

Docs 를 마크다운으로 내보내면 이미지 자리가 `![alt](blob/<id>)` 로 남는다. alt 는 살아 있고 파일만 빠진다. 그래서 파일만 순서대로 짝지으면 된다.

1. Docs 에서 평소처럼 이미지를 넣고 alt 를 쓴다
2. Docs 에 넣은 이미지 파일을 같은 순서로 폴더 하나에 따로 받아 둔다. 이름순이 글 순서와 같도록 `01.png`, `02.jpg` 처럼 번호를 붙인다
3. 명령에 `--images <폴더>` 를 준다. 글의 n 번째 `blob/` 자리를 폴더의 이름순 n 번째 파일에 짝짓는다

```bash
pnpm blog lint 글.md --images ./글-이미지
```

자리 수와 파일 수가 다르면 오류가 난다. 순서가 틀리면 검사로는 잡히지 않으므로 `preview` 에서 그림과 캡션이 맞는지 눈으로 확인한다.
